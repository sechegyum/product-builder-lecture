# 블로그 글 뼈대 — 고정

**모든 종목 글은 이 순서로 쓴다.** 회차마다 바꾸지 않는다.
(2026-10-09 확정. 이전의 `급등 이유 → 규모 → 재무 → 리스크 → 지표 → 정리`
순서를 이것으로 **대체한다.** `SNS-TEMPLATE.md` 의 블로그 절은 이 파일을 따른다.)

---

## 제목

**종목명 + 이벤트/질문**, 공백 제외 20~25자.
핵심 키워드를 앞 8글자 안에 둔다. 검색어를 그대로 넣는다.

```
OO전자 3분기 실적 발표, 주가 빠진 진짜 이유
OO 주가 전망, PER로 따져본 지금 가격
OO 왜 급등했을까? 공시 한 줄로 정리
```

제목 안은 **5~7개를 글자 수와 함께** 뽑고 추천 하나를 이유와 같이 짚는다.

## 대표사진

**종목명 + 핵심 숫자 하나** (예: `영업이익 +32%`).
`thumb.py` 의 `num` 또는 `vs` 레이아웃으로 만든다.

- 직접 만든 이미지만 쓴다
- **핵심은 가운데 정사각 영역에.** 네이버가 어디서 자를지 모른다
- 한 줄 6~9자. 검색 결과의 작은 칸에서 그 이상은 안 읽힌다

## 본문 순서

### 머리 — 인사 + 기준 표기

```
안녕하세요. 스냅베스트(Snapvest)입니다.
오늘 다루어볼 종목은 {회사명}({티커})입니다.

📅 2026.00.00 종가 기준 / 작성자 보유 여부: 보유 · 미보유
```

**보유 여부를 매 글 밝힌다.** 이해관계를 먼저 까는 것이 글의 신뢰를 만든다.

### ① 3줄 요약 — 결론 먼저

형광펜으로 칠한다.

```
▪ 무슨 일이 있었나
▪ 숫자로 보면
▪ 내 관점 한 줄
```

### ② 왜 지금 이 종목?

실적·공시·뉴스 촉매를 2~3줄. **무엇이 이 글을 쓰게 했는지**를 먼저 댄다.

### ③ 한눈에 보는 핵심 지표  **[에디터 표]**

`시가총액 · PER · PBR · 배당수익률 · 52주 고/저 · 평균 목표가`

**네이버 에디터의 표 기능으로 넣는다. 이미지로 만들지 않는다.**
에디터 표는 글자라서 검색에 걸리고, 모바일에서 알아서 접히고,
읽는 사람이 복사할 수 있다. 표를 그림으로 만들면 이 셋이 전부 사라진다.

마크다운 표(`|`)를 붙여넣는 건 여전히 안 된다. 그건 깨진다.
**에디터 표 기능 ≠ 마크다운 표** — 둘을 헷갈리지 않는다.

### ④ 실적 흐름  **[이미지]**

최근 4~8분기 매출·영업이익 그래프 한 장.
→ 전년 대비 증감 + **원인 한 줄 해석**. 숫자만 두지 않는다.

### ⑤ 투자 포인트 vs 리스크 — **같은 비중으로**

```
[상승 논리]  1.  2.  3.
[하락 리스크] 1.  2.  3.
```

**개수를 맞춘다.** 한쪽이 길면 그 순간 글이 아니라 광고가 된다.

### ⑥ 경쟁사 비교  **[에디터 표]**

`기업 · PER · 영업이익률 · 매출 성장률`
→ ③번과 같이 에디터 표 기능으로.

### ⑦ 내 관점

지금 가격을 어떻게 보는지 + **그렇게 본 근거**.

**단정하지 않는다.** 조건문으로 쓴다.

```
✕  지금이 저점이니 담을 만합니다
⭕ 4분기 영업이익률이 두 자릿수를 회복하면 긍정적으로 봅니다
   그 전까지는 판단을 미룹니다
```

### ⑧ 다음 체크포인트

다음 실적 발표일 / 지켜볼 지표 / 후속 글 예고.
**재방문을 만드는 자리다.**

### ⑨ 자주 묻는 질문

```
Q. 배당은 언제, 얼마?
Q. 증권사 평균 목표가는?
Q. 가장 큰 리스크는?
```

그 회차에 맞는 질문으로 갈아도 되지만 **세 개는 유지한다.**

### ⑩ 출처

DART 공시 / 회사 IR 자료 / 참고 기사
+ 더 자세한 분석 링크 하나 (선택)

**외부 링크는 글 전체에서 1개 이하.** 출처는 링크 없이 이름만 적어도 된다.
링크가 많으면 체류시간이 밖으로 샌다.

### ⑪ 면책 — 매 글 고정

```
본 글은 개인 공부 기록이며 투자 권유가 아닙니다.
투자 판단과 책임은 본인에게 있습니다.
```

### 끝인사 — 질문 하나

**댓글을 유도하는 질문 한 줄로 닫는다.** 그 회차 내용에 걸린 질문이어야 한다.

```
✕  어떻게 보시나요?
⭕ 레드와이어 비중 17%, 이건 기회로 보시나요 위험으로 보시나요?
```

### 맨 끝 — 고정 띠 + 태그

```
[band-app.jpg]        <- cardnews/thumbs/, 모든 글 동일
태그 30개             <- 고정 15 + 회차별 15 (SNS-TEMPLATE.md 참고)
```

## 같이 지키는 것

- **문체는 해요체.** `~입니다` 와 섞지 말고 `~이에요` `~해요` 로 통일
- **표는 전부 이미지.** 본문에는 `▪ 이름 — 값` 줄로 쓴다
- **공백으로 줄을 맞추지 않는다.** 붙여넣으면 무너진다.
  연혁도 `▪ 날짜 — 내용` 한 줄씩
- **확인 안 된 값은 `자료 없음`.** 추정값을 쓸 때는 `(역산)` 을 붙인다
- **사진은 6~9장.** 직접 만들거나, 아니면 출처를 적는다
- **이미지마다 대체 텍스트.** 네이버가 읽는다
- 서비스 홍보 문구는 글귀에 쓰지 않는다. 맨 끝 띠가 그 일을 한다

## 쓰는 순서

```
1. 자료 검증          숫자가 서로 맞는지 먼저 계산한다
2. 대표사진           thumb.py num 또는 vs
3. ④ 그래프
4. 본문               위 순서대로 (③⑥ 표는 에디터에서 직접)
5. 제목 안 5~7개
6. 토스 · 인스타 · 쓰레드   (한 번에 같이)
```

> `thumb.py` 의 `table` 레이아웃은 **인스타·쓰레드용으로만** 남긴다.
> 거기는 에디터 표를 못 쓰니 그림이어야 한다. 블로그 본문에는 안 쓴다.

# 발행 전 체크리스트

```
□ 제목: 종목명 + 구체적 질문 (공백 제외 20~25자)
□ 기준일 · 보유 여부 표기
□ 사진 6~9장 (직접 제작 or 출처 표기)
□ 지표·비교는 에디터 표 기능 (이미지 X)
□ 투자 포인트 vs 리스크 같은 비중
□ 내 관점 + 근거
□ 출처(DART/IR) + 면책 문구
□ 외부 링크 1개 이하
□ 모바일 미리보기 확인
□ 글 끝 질문 1개 (댓글 유도)
```

# 발행 후

```
□ 1~2일 뒤 키워드 검색으로 노출 확인
□ 댓글 답글 달기
□ 다음 글(후속 실적·체크포인트) 일정 잡기
```

**발행 후 세 줄을 빼먹지 않는다.** 노출 확인은 다음 글의 제목을 정해 주고,
댓글 답글은 체류시간을 늘리고, 후속 글 일정은 ⑧번에 적은 체크포인트와
짝이 된다. ⑧에 적어 놓고 안 쓰면 그 약속이 거짓말이 된다.

# 이미지 만들 때 (고정)

## 1. 그래프는 이렇게

```
결론이 제목      "3분기 영업이익 +32%"  — 'OO 실적 추이' 가 아니라 답을 적는다
단위 표기        "(단위: 억원)"          — 없으면 숫자를 못 읽는다
강조만 색        말하려는 막대 하나만 색, 나머지는 회색
0부터 시작       축을 잘라 올리면 과장이 된다
출처·기준일      "출처: DART · 10.09 기준"  — 그림 안에 박는다
```

## 2. 폰 화면에서 읽히게

- **1080×1080 기준 본문 36~40px 이상, 제목 70px 이상.**
  폰에서는 실제 크기의 **1/3** 로 줄어 보인다. 28px 로 적으면 폰에서 9px 다
- **이미지 한 장에 글씨는 3줄 이하.** 긴 설명은 본문 텍스트로 쓴다.
  그래야 검색에도 걸린다
- **글자·그래프는 PNG, 사진은 JPG.** 그래프를 JPG 로 저장하면 글자 테두리가 뭉개진다
- **투명 배경 PNG 는 쓰지 않는다.** 네이버 앱 다크모드에서 글자가 안 보인다.
  배경은 항상 칠해 둔다

### PNG 가 너무 클 때

우리 배경이 매끄러운 보라 그라데이션이라 PNG 압축이 거의 안 먹는다.
**JPG 로 바꾸지 말고 색수를 줄인다.** `thumb.py` 가 자동으로 한다.

| | 원본 PNG | 128색 PNG | JPG q90 |
|---|---:|---:|---:|
| 비교표 1080×1158 | 455KB | **131KB** | 159KB |
| 끝 띠 1080×700 | 289KB | **87KB** | 77KB |

128색으로 줄이고 디더링을 걸면 **JPG 보다 작으면서 글자는 PNG 그대로**다.

## 3. thumb.py 가 지키는 것

```
python3 thumb.py <설정.json> thumbs
```

- 글자·그래프 레이아웃(`num` `vs` `ask` `list` `table` `band`) → **PNG 128색**
- 사진 레이아웃(`photo` `split`) → **JPG q90 · 4:4:4**
- 표 값이 칸을 넘치면 그 칸만 글자를 줄인다 (이웃 칸과 붙는 것보다 낫다)
- 글자 크기는 위 기준에 맞춰져 있다. 임의로 줄이지 않는다

# 썸네일 문구 공식 (고정)

썸네일은 글이 아니라 **간판**이다. 다 읽히길 기대하지 않는다.
네 가지 틀 중 하나를 고르고, 거기 맞는 말만 넣는다.

## 네 가지 틀

### 숫자형 — 실적 발표

```
라벨    실적리뷰 #N
메인    +32%  ·  -15%  ·  역대 최대
보조    종목명 + 무엇의 숫자인지
```

### 질문형 — 밸류에이션 · 논란

```
라벨    종목분석
메인    지금 비쌀까?  ·  아직 쌀까?
보조    무엇으로 따져봤는지 (PER, 목표가)
```

### 비교형 — 경쟁사

```
메인    A사 vs B사
보조    누가 더 쌀까  ·  누가 더 벌까
```

### 이유형 — 급등락 · 이슈

```
라벨    이슈정리
메인    급락한 이유  ·  급등한 이유
보조    N가지 (숫자 배지)
```

## 공통 규칙

- **큰 글씨 1개, 전체 10자 안팎.** 큰 글씨가 둘이면 둘 다 안 읽힌다
- **폰트 2개 이하, 컬러 2~3개 고정.** 매번 새로 고르면 블로그가 흩어진다
- **좌상단 시리즈 라벨, 하단 블로그명.** 포맷이 달라도 한 블로그로 읽히게 하는 두 장치
- **엄지손톱 크기 테스트.** 축소해서 메인 문구가 안 읽히면 다시 만든다

## thumb.py 로 옮기면

| 공식 | layout | 쓰는 필드 |
|---|---|---|
| 숫자형 | `num` | `tag:"실적리뷰 #3"` `big` `tone` `lines[2]` |
| 질문형 | `ask` | `tag:"종목분석"` `lines[1~2]` `sub` |
| 비교형 | `vs` | `left` `left_note` `right` `right_note` `caption` |
| 이유형 | `list` | `tag:"이슈정리"` `badge:"3가지"` `title` `items[3]` |

- `tag` 가 **좌상단 라벨**(알약), `badge` 가 그 옆 **숫자 배지**다
- **하단 블로그명은 자동**으로 들어간다. `note` 에 근거를 적으면 그 자리를 가져간다.
  일부러 비우려면 `"note": ""`
- 메인 문구가 10자를 넘으면 만들 때 `⚠ 10자 넘음` 이 뜬다. 잘라서 다시 넣으라는 뜻
- **판은 두 벌.** `"theme": "dark"` 를 넣으면 어두운 남보라 판이 된다.
  같은 뼈대라도 밝은 판과 번갈아 쓰면 목록에서 덜 지친다

```
python3 thumb.py thumbs-formula.json thumbs    # 네 틀의 견본
```
