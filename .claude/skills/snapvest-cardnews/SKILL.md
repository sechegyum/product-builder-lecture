# 스냅베스트 카드뉴스 제작

사용자가 **종목과 뉴스만** 던진다. 나머지(주가, 시총, 거래량, 공매도, 임상/공시 세부)는
직접 조사해서 채운다. 되묻지 말고 조사부터 한다.

작업 폴더: `cardnews/`

---

## 절대 규칙

1. **`generate.py` 의 디자인 코드를 수정하지 않는다.** 색상 상수, 좌표, 폰트 크기 전부 고정.
   사용자가 명시적으로 요청할 때만 해당 `cardN()` 함수 **하나만** 고친다.
2. **결론을 내지 않는다.** `지금이 매수 타이밍` ✕ → `공매도가 8.2%p 늘었어요` ⭕
3. **모르는 건 모른다고 쓴다.** 확인 안 된 값은 `자료 없음` / `미공개` 로 그대로 노출한다.
   이게 이 계정의 신뢰 장치다. 그럴듯한 숫자를 지어내지 않는다.
4. **숫자를 제목에 넣는다.** `공매도 급증` ✕ → `공매도 19.3%, 2주 만에 8.2%p` ⭕
5. 말투는 `~어요`, `~습니다`. 기사 헤드라인을 복사하지 않는다.

## 순서

### 0. 이전 회차 보관

```
cd cardnews && python3 archive.py
```

`config.json`, `SOURCES.md`, `sns.md`, `photos/`, `assets/`, `out/`, `png/` 를
`archive/YYYY-MM-DD-TICKER/` 로 옮긴다. 템플릿 파일은 그대로 남는다.

### 1. 조사

WebSearch 로 아래를 모은다. **이 환경에서는 야후·나스닥·stockanalysis 등
시세 API 와 대부분의 금융 사이트가 프록시에 막혀 있다. WebSearch 요약만 쓸 수 있다.**

| 항목 | 쓰이는 카드 |
|---|---|
| 종가 · 등락률 · 전일 종가 | 1 |
| 시가총액 | 2 |
| 거래량 (3개월 평균 대비 몇 배) | 1·2·4 |
| 52주 위치 (신고가 / 상위 N%) | 2 |
| 공매도 비중 · 변화 | 1 |
| 급등·급락 사유의 **구체 수치** (임상이면 환자 수·평가변수·시험명) | 3 |
| **아직 공개되지 않은 것** | 3 |

마지막 줄이 제일 중요하다. "무엇이 아직 안 나왔는지" 가 이 카드뉴스의 차별점이다.

### 2. 사진

`cardnews/photos/` 에 넣고 `python3 make_photos.py` 를 돌린다.

- **2번 카드** — 회사 로고나 시설 사진
- **3번 카드** — 뉴스 소재 관련 (임상이면 실험실, 공장 증설이면 공장)
- **표지 원형 로고** — Brandfetch MCP 로 티커 조회. CDN 이 막혀 있으니
  `bf://asset/{도메인}/icon` 리소스로 바이트를 받는다. `photos/` 에 놓고
  `make_photos.py` 의 `CHIP` 파일명을 바꾼다
- **언론사 기사 사진은 쓰지 않는다.** 무료 스톡이나 회사 공식 자료만
- 원본이 작아도 된다. 전처리기가 흐린 배경 + 최소 배율 전경으로 겹쳐 채운다

사진이 없으면 `photo_company` / `photo_reason` 을 비운다 → 점선 플레이스홀더가 나온다.

### 3. config.json

`cardnews/README.md` 3번 항목에 필드 표가 있다. 헤드라인 문형은 **고정**이다.

| # | 문형 |
|---|---|
| 1 | `{종목}는 왜 / 하루 만에 / N% 올랐을까?` |
| 2 | `{종목}는 어떤 회사일까?` |
| 3 | `그래서 왜 올랐을까?` |
| 4 | `지표는 지금 어디쯤일까?` |
| 5 | `그럼 내부자는 지금 사고 있을까?` |

질문 → 배경 → 답 → 검증 → **답 안 준 질문**. 5번이 유료 항목으로 끝나서 유입이 생긴다.

**표지는 정렬만 다른 두 장이 나온다.** `generate.py` 가 알아서 둘 다 만든다.

| 파일 | 정렬 |
|---|---|
| `1-cover.svg` / `.png` | 우측 |
| `1-cover-center.svg` / `.png` | 중간 |

인스타 피드에서 좌측 정렬이 UI 에 가려서 우측·중간 두 안을 두고 고른다.
첫 줄의 종목명만 굵게(900) 나가는데 `company_ko` 로 자동 인식하므로
`cover_line1` 은 **반드시 종목명으로 시작**하게 쓴다.

**글자 넘침 주의** — 렌더 후 눈으로 확인한다. 대략 한도:

| 필드 | 크기 | 한도 |
|---|---|---|
| `cover_fact1~2` | 27px | 30자 |
| `desc_lead1~2` / `reason_lead1~2` | 38px | 25자 |
| `desc_sub` | 27px | 34자 |
| `reason_body` 각 줄 | 28px | 33자 |

### 4. 차트 (4번 카드)

실제 OHLCV 를 구할 수 있으면 `candles` 에 `[[o,h,l,c,vol비율], ...]` 로 넣는다.
못 구하면 `candle_start` / `candle_end` / `seed` 자동 생성을 쓰되:

- `candle_end` = 실제 종가
- **직전 봉 종가가 실제 전일 종가에 맞도록 `seed` 를 탐색한다** (수백 개 돌려서 오차 최소)
- `gauge_note` 에 추정치임을 명시하고 `SOURCES.md` 경고표에 적는다

MFI / RSI / 볼린저 %B 는 출처를 못 구하면 **추정치임을 반드시 표기**한다.
급등 직후 RSI 는 90 이상, %B 는 1.0(상단 돌파) 이 수학적으로 거의 확정이지만
정확한 자릿수는 지어낸 값이다. 백엔드 값으로 교체하라고 사용자에게 말한다.

### 5. 생성 · 렌더

```
cd cardnews
python3 make_photos.py
python3 generate.py config.json out
python3 render.py
```

렌더된 PNG 5장을 **직접 눈으로 확인한다.** 글자 넘침, 사진 잘림, 하단 잘림을 본다.

### 6. SOURCES.md

`SNS-TEMPLATE.md` 옆에 회차별 `SOURCES.md` 를 새로 쓴다. 숫자마다 근거 한 줄.
마지막에 **`⚠ 아직 실데이터가 아닌 값`** 표를 넣는다. 이 표가 비어야 게시 가능한 상태다.

### 7. SNS 글귀

`cardnews/SNS-TEMPLATE.md` 뼈대로 인스타 캡션 + 쓰레드 체인 5개를 쓰고
`cardnews/sns.md` 에 저장한다. 카드뉴스와 한 세트다.

### 8. 커밋

```
git add -A cardnews && git commit && git push -u origin <브랜치>
```

컨테이너가 날아가면 커밋 안 한 건 사라진다. **매 회차 반드시 커밋한다.**

## 사용자에게 보고할 때

- 실제로 채운 수치를 표로 보여준다
- **아직 실데이터가 아닌 항목을 반드시 따로 짚는다** (차트 캔들, 지표 게이지)
- 출처를 링크로 단다
- **PNG 6장**을 `SendUserFile` 로 보낸다 — 표지 2종(우측·중간) + 2~5번
- 표지는 둘 중 어느 쪽을 쓸지 사용자가 고르게 둔다
